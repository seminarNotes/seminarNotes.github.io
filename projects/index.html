Python-based Financial Data ETL Pipeline Development
2022.04 – 2022.07 | KISpricing Financial Engineering Research Group

1. Project Overview

  • Project Name : Financial Market Data Automated Collection and Storage Pipeline Development
  • Project Period : April 2022 - July 2022
  • Role : Sole Designer and Developer
  • Tech Stack : Python, Celery, APScheduler, MariaDB, Oracle, Excel Premium API

2. Project Objective

The main objective was to automate the collection of stock derivatives market data, which had previously been manually collected through external vendors, in order to improve data collection stability and quality while reducing costs.

3. Key Implementation Details

  • Data Collection Automation: Built an automated pipeline to collect KOSPI and HSCEI options market data using CHECK Expert API and Excel Premium API
  • ETL Process Design: Designed and implemented the full ETL (Extract, Transform, Load) pipeline, including text format conversion, transfer to processing servers, and final database storage
  • Scheduling and Task Management: Efficiently managed job scheduling and parallel processing using Celery and APScheduler
  • Quality Validation and Documentation: Implemented data quality validation processes and created full system specification documentation to ensure maintainability

4. Outcomes and Impact

  • Cost Reduction: Achieved annual cost savings of approximately 8,268 GBP (≈ 13,165,000 KRW based on 2022 average exchange rate of 1 GBP ≈ 1,592.31 KRW)
  • Data Quality Improvement: Improved data quality by approximately 24.45% through automated collection and validation processes

5. Technology Stack Used

Python, Celery, APScheduler, MariaDB, Oracle, Excel Premium API

SABR-based Stock Option Volatility Valuation Model Automation
2022.07 – 2023.02 | KISpricing Financial Engineering Research Group

1. Project Overview

  • Project Name : SABR-based Stock Option Volatility Valuation Model Automation
  • Project Period : July 2022 - February 2023
  • Role : Model transition design and automation logic implementation
  • Tech Stack : Python, Excel VBA, MariaDB, Oracle, Telegram Bot (API)

2. Project Objective

The existing Excel VBA-based Log-Normal Mixture volatility model had a large number of parameters and strong nonlinearity, frequently leading to local-minima issues during calibration. As a result, manual parameter adjustments by users were an essential part of the workflow. This project aimed to improve the stability of volatility-curve generation and enable fully automated operations by transitioning the valuation framework to a SABR-based approach, which uses fewer parameters and provides a more interpretable curve structure.

3. Key Implementation Details

  • Volatility model transition: Migrated from the existing mixture-model framework to a SABR-based volatility surface generation pipeline, reducing the parameter count and improving calibration stability
  • Automated parameter calibration logic: Converted user experience-based manual adjustment rules into a rule-based algorithm to establish a fully automated calibration process
  • Python-based volatility generation automation: Replaced the Excel VBA calculation workflow with a Python-based computation engine to automatically generate and calibrate volatility curves
  • Operational automation system: Implemented an end-to-end automation pipeline including volatility generation, database storage, curve visualization output to the server, and Telegram notifications for summarized results

4. Outcomes and Impact

  • Process time reduction: Reduced the time required for volatility-curve generation and validation from approximately 5 hours to about 30 minutes (≈ 90% reduction)
  • Improved automation level: Converted a semi-automated workflow with manual adjustments into a fully automated system
  • Enhanced operational stability: Improved reproducibility and stability of volatility curve generation by reducing the number of calibration parameters
  • Infrastructure efficiency improvement: Optimized data storage architecture to improve server storage utilization efficiency

5. Technology Stack Used

Python, Excel VBA, MariaDB, Oracle, Telegram Bot (API)
