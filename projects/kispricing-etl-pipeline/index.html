Project Overview

This project involved designing and implementing an automated data collection and storage pipeline for stock derivatives market data. The system replaced manual data collection through external vendors, improving stability, quality, and reducing operational costs significantly.

  • Project Name: Financial Market Data Automated Collection and Storage Pipeline Development
  • Duration: 4 months (April – July 2022)
  • Team Size: 1 person (solo developer)
  • Data Sources: KOSPI options, HSCEI options, foreign exchange futures
  • Update Frequency: Daily automated collection during market hours

Project Objective

The main challenge was to replace manual, vendor-dependent data collection with a fully automated pipeline. This required:

  • Eliminate manual intervention: Previously, market data was collected through external vendors and manually processed;
  • Improve data quality: Reduce collection errors and inconsistencies through automated validation;
  • Reduce costs: Lower operational expenses by eliminating vendor fees and staff overhead;
  • Ensure reliability: Create a robust system capable of handling failures and retry logic.

System Design and Implementation

2.1 ETL Pipeline Architecture

The pipeline follows a classical Extract-Transform-Load (ETL) pattern:

\text{Data Source} \xrightarrow{\text{Extract}} \text{Raw Data} \xrightarrow{\text{Transform}} \text{Processed Data} \xrightarrow{\text{Load}} \text{Database}

Extract

  • Integrated with CHECK Expert API for real-time options data;
  • Used Excel Premium API for alternative data feeds;
  • Scheduled collection at market-dependent intervals (e.g., 15-min snapshots).

Transform

  • Text format conversion (CSV, fixed-width, JSON);
  • Data normalization and type casting;
  • Validation rules to detect missing or anomalous values;
  • Integration with intermediate processing servers.

Load

  • Stored in MariaDB for transactional queries;
  • Mirrored to Oracle for enterprise reporting;
  • Implemented batch insert with transaction rollback on errors.

2.2 Job Scheduling and Parallelization

To handle multiple data sources and high-frequency updates, the system uses:

  • Celery: Distributed task queue for parallel processing across multiple workers;
  • APScheduler: Lightweight job scheduler for periodic and cron-based tasks;
  • Redis/RabbitMQ: Message broker for task coordination.

2.3 Data Quality and Monitoring

Quality assurance measures included:

  • Schema validation (column types, mandatory fields);
  • Range checks (e.g., prices within market limits);
  • Duplicate detection using checksums;
  • Logging and alerting for failed collection cycles.

Results and Impact

3.1 Cost Reduction

The automated system eliminated vendor-dependent data collection, achieving:

Metric Annual Cost Savings
Vendor data subscription fees Before: ~£16,536 ~£8,268 (50%)
Manual processing labor Before: ~2 FTE 1–1.5 FTE reallocated
Total Annual Savings ≈ £8,268 (~13.2M KRW at 2022 rates)

3.2 Data Quality Improvement

Automated validation and consistency checks improved data reliability:

  • Error Rate Reduction: Manual collection had ~5.2% error rate; automated pipeline achieved <0.4% (92% improvement);
  • Consistency: All data points subject to identical validation rules, eliminating human-induced variability;
  • Completeness: Missing data handling and retry logic increased data completeness from ~94% to 99.8%.

Overall data quality improvement: 24.45%

3.3 Operational Benefits

  • Automation: 100% hands-off during market hours; failure notifications via email/Slack;
  • Scalability: Architecture supports adding new data sources with minimal additional overhead;
  • Audit Trail: Complete logging enables regulatory compliance and debugging;
  • Recovery: Implemented checkpoint/restart logic for failed jobs.
